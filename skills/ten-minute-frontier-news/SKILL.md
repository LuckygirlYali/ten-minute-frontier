# 十分钟前沿新闻生产

为 `ten-minute-frontier` 生成一份十分钟可读的公开日报。输出中文，关键英文术语保留原文。

开始前完整读取：

- `references/editorial-policy.md`：选题、评分、事实与观点规则。
- `references/data-schema.md`：日报 JSON 契约。
- `references/publishing.md`：验证、提交、恢复和失败边界。

## 固定配置

- 时区：`Asia/Shanghai`
- 主任务：每天 08:00 开始，目标 08:30 前上线。
- 恢复任务：每天 09:00；当天日报存在且已推送时直接结束。
- 采集窗口：从上一期 `windowEnd` 到当前运行时刻；首次运行最多回看 48 小时。
- 受众：每天只有十分钟了解 AI、科技和商业前沿的中文研究生。
- 首页软上限：3–5 条重大、最多 15 条值得关注，其余为速览。

## 工作流

### 1. 检查状态

1. 读取最新一期日报、配置和历史文章 ID。
2. 调用 Supabase RPC `get_recommendation_signals`（环境已配置时），把站主反馈按 70%、其他用户汇总按 30% 转成选题信号；反馈不能覆盖事实质量门槛。
3. 如果处于恢复任务且当天文件已存在、内容验证通过、远程已含对应提交，立即成功结束。

### 2. 采集候选

必须同时执行以下通道，任一通道失败都记录原因：

1. 运行 `python3 scripts/rss_fetch.py` 获取 RSS 候选。
2. 使用网页搜索补充当日 AI、科技、商业、产业政策、宏观经济和广泛国际政治信号。
3. 逐查高优先级一手源：主要 AI 实验室与科技公司官方新闻页、政府/监管机构、论文或项目原页。
4. 用 AI HOT、GitHub Trending、Hacker News 等聚合源发现线索，但不把热度当事实，也不把聚合页当原始来源。

把所有采集到的 URL 保存为来源池。不要从标题猜测、拼接或凭记忆替换 URL。

### 3. 去重与核验

1. 按规范化 URL、主体、事件和标题语义合并同一事件。
2. 重大信息优先要求官方源或两个独立可靠来源；仅有一个可靠来源时明确标记单源。
3. 数字、日期、金额、公司和政策结论必须回到原文核验。
4. 社交媒体和个人观点只能进入“观点”，不能独立证明事实。
5. 付费内容只有在官方或第二可靠来源可验证时收录，并标注付费。
6. 来源池不存在的链接直接删除；宁可漏掉，不得编造。

### 4. 分类与评分

每条只选一个主分类：`AI`、`科技`、`商业`、`宏观国际`。

使用以下权重计算 0–100 分：

- 产业或社会影响 30%
- 与 AI、科技、商业相关性 25%
- 新颖性与变化幅度 10%
- 来源可靠性 20%
- 多源关注度 10%
- 历史反馈 5%

据此标记 `重大`、`值得关注`、`速览`，但保留编辑复核。没有明确产业影响的广泛政治新闻最高只能是“速览”。

### 5. 写作

每条必须分开写：

1. 中文标题。
2. 首页事实摘要：只保留理解这条新闻所需的核心事实。
3. `briefing`：标题链接打开的站内短报道。重大新闻 200–350 字；值得关注 60–120 字；速览 30–60 字。不为达到字数增加信息。
4. `视野`：可选的编辑信息增量；如果不能说明具体变化、约束、竞争关系或后续变量，就省略该字段。
5. 类别、发布时间、内容类型、原始来源和验证来源。

准确优先于完整，完整优先于精彩。事实摘要不掺入推断；主体宣传、预测和未证实消息必须注明归属与确定程度。观点条目明确标记“观点”，不写成已发生事实。不要凑数量。标题、短报道、视野和发布前自检的完整规则见 `references/editorial-policy.md`。

### 6. 质量门禁

发布前必须全部通过：

1. 采集通道执行状态完整，失败项有记录。
2. 信源健康率达到 70%，或日报明确显示信源缺失。
3. 跨日和当日去重完成。
4. 每个来源 URL 来自来源池且指向具体内容页。
5. 关键事实与评分字段完整。
6. 运行 `node scripts/validate-digests.mjs`。
7. 运行 `python3 skills/ten-minute-frontier-news/scripts/verify_digest_links.py <生成的 JSON 文件>`；401/403/429 可警告，其他断链必须移除或修正。
8. 运行 `npm test` 和 `npm run build`。

任一硬门禁失败都停止发布，不覆盖上一期。

### 7. 原子发布

1. 将完整日报写入临时路径并验证，只有全部通过后才移动到正式日期文件。
2. 只暂存本次新增或修改的日报及必要索引文件。
3. 使用 Conventional Commit：`content(digest): publish YYYY-MM-DD briefing`。
4. 正常推送当前跟踪分支，不使用 force，不修改 Git 配置。
5. 成功时保持安静；失败时报告失败阶段、已保留的文件和恢复建议。

## 无重大更新

仍可发布合法日报，设 `status: no-major-updates`，`items` 只保留真正有价值的速览；首页明确写“今日无重大更新”。绝不降低门槛填满版面。

## 事实更正

次日处理迟到新闻。发现历史事实错误时更新原条目 `correction` 字段，明确更正时间和内容，不静默改写。
