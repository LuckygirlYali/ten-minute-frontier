# 发布与恢复

## 主任务

每天 08:00 北京时间启动。读取最新一期 `windowEnd`，完成增量采集、写作、质量门禁、构建、提交与推送，目标 08:30 前完成。

不要直接编辑线上部署产物。GitHub Pages 只从 `main` 的成功构建发布；构建失败自然保留上一版。

## 恢复任务

每天 09:00 北京时间检查：

1. 当天 JSON 文件是否存在。
2. 内容验证和构建是否通过。
3. 当前分支是否已推送到远程。

三项都满足就结束。否则从最近成功阶段重试一次。不要重复采集已经写入且通过验证的内容，不要重复提交相同文件。

## Git 安全

- 检查 `git status --short --branch`、当前分支和远程。
- 只暂存本轮归属文件，不提交 `.env`、密钥或无关修改。
- 不修改 Git 配置，不跳过钩子，不 force push。
- 远程领先时只尝试一次安全 fetch/rebase；冲突即停止并报告。

## 通知

成功时不通知。失败时说明：失败阶段、错误摘要、线上仍显示哪一期、是否已经生成可恢复的本地草稿、下一步建议。
